# LLM-QAT: Data-Free Quantization-Aware Training, explained simply

**Paper:** Zechun Liu, Barlas Oğuz, Changsheng Zhao, Ernie Chang, Pierre Stock, Yashar Mehdad, Yangyang Shi, Raghuraman Krishnamoorthi, Vikas Chandra (Meta AI), *LLM-QAT: Data-Free Quantization Aware Training for Large Language Models*, 2023.

**In one sentence:** instead of only rounding a trained LLM's numbers (post-training quantization, PTQ), **keep training it while it is quantized** (quantization-aware training, QAT). The original training data isn't available, so **let the full-precision model generate its own training text** and distil its predictions into the quantized copy. This makes 4-bit weights **and** a 4-bit KV cache work where PTQ methods fail.

---

## 1. PTQ vs QAT
- **PTQ** (papers 074–077: SmoothQuant, GPTQ, AWQ): take a trained model, choose scales or adjust weights a little using a small calibration set. There is **no real training**. It is fast, but it breaks down at low bit widths, especially for activations and the **KV cache**.
- **QAT:** simulate quantization in the forward pass during training, so the model learns weights that survive rounding. It is much better at low bits, but it needs **training data**:
  - for LLMs, the pre-training corpus is huge and often not available;
  - fine-tuning on a small public set (e.g. WikiText) **over-fits** and hurts zero-shot ability.

---

## 2. Three design choices

### (1) Data-free distillation
- **Generate the training data from the model itself.** Start from the start token, pick the next token, append it, and repeat.
  - **Always top-1:** generations are repetitive and lack diversity.
  - **Always sampling:** diverse, but noisier.
  - **Hybrid (the paper's default):** top-1 for the **first 3–5 tokens**, then sample.
- **Scale:** 100k sequences (up to 1,024 tokens) generated by LLaMA-7B.
- **Why this works:** generated text reflects the model's own training distribution, so the quantized model stays a **general** model. In Table 3, fine-tuning on WikiText over-fits and C4 transfers poorly to zero-shot tasks; generated data generalises best, and sampled data beats top-1.

### (2) Logits distillation
- **The teacher:** the full-precision model gives a full next-token distribution p_T at every position.
- **The loss:** the student (the quantized copy) minimises the cross-entropy against it:
```
L = − (1/n) Σ_i Σ_c p_T(c | x_i) · log p_S(c | x_i)          (Eq. 4)
```
- **Why soft labels:** the sampled next token is a noisy label, while the teacher's full distribution is much more informative. Adding attention-map or hidden-state distillation **hurt**.

### (3) The quantizer
- **Symmetric MinMax, no clipping:**
```
X_q = α · round(X / α),     α = max|X| / (2^(N−1) − 1)
```
- **No clipping:** LLMs have important outliers (papers 074, 076), and clipping them made perplexity explode past 10,000.
- **Granularity:**
  - weights: per **output channel**;
  - activations: per **token**;
  - **KV cache: per token**, since keys and values are produced one token at a time.
  - The KV cache takes huge memory for long contexts, and few earlier works quantized it.
- **Training through rounding:** the **straight-through estimator (STE)**. In the forward pass round() is applied; in the backward pass it is treated as the identity (its true gradient is 0 almost everywhere).

**Worked example (STE):** x = [0.3, −1.2, 0.05, 2.0] at 4 bits per token.
- α = 2.0/7 = 0.2857, giving [0.286, −1.143, 0, 2.0].
- The gradient of their sum with respect to x is [1, 1, 1, 1]: it passes straight through.

**Settings** are written **W-A-KV**, e.g. 4-8-4 means 4-bit weights, 8-bit activations and a 4-bit KV cache.
**Training:** AdamW, learning rate 2e-5, cosine decay.

---

## 3. Results (LLaMA 7B / 13B / 30B)
- **At 8-8-8**, everything (PTQ and QAT) is fine.
- **Below 8 bits** for any of W, A or KV, PTQ methods (RTN, GPTQ, SmoothQuant) lose accuracy; LLM-QAT holds up.
- **30B examples:**
  - **8-8-4:** LLM-QAT **69.7** vs SmoothQuant **50.7** average zero-shot accuracy;
  - **4-8-8:** LLM-QAT beats the best PTQ (RTN) by 1.4 points;
  - **4-8-4:** **all PTQ methods fail**, while LLM-QAT gets **69.9**, only 1.5 below full precision.
- **It combines with SmoothQuant** for 4-bit-weight, 6-bit-activation settings.

---

## 4. Why it matters
- **The first practical QAT for LLMs.** Its key move, using the model's own generations as data, removes QAT's biggest obstacle.
- **It shows that the KV cache can be quantized to 4 bits**, which matters for long contexts and large batches.
- **Distilling a compressed model on the original model's own outputs** became a common tool in later compression work (pruning and distillation into smaller models).

## 5. What our code found
- **The model:** a tiny LLaMA (paper 056) trained to model **whole** sequences `<BOS> task x1..x6 SEP y1..y6`, so it can generate them. Answer accuracy 98.0%.

**Generating data** (3,000 sequences):

| Mode | Distinct sequences | Valid task instances | Task mix |
|---|---|---|---|
| Top-1 always | 0.0% (one sequence) | 100% | sort only |
| **Sample always** | **99.9%** | 95.6% | copy 974 / reverse 984 / sort 1,042 |
| Hybrid (top-1 for 3 tokens) | 88.0% | 91.8% | **sort only** |

**Honest note:** the hybrid scheme fails in our toy. Our first generated token *chooses the task*, so making it deterministic leaves only "sort". In natural text the first few tokens matter less.

**PTQ (round-to-nearest)**, W-A-KV:

| Setting | 8-8-8 | 4-8-8 | 4-8-4 | 4-6-4 | 3-8-8 | 3-8-3 | 2-8-8 |
|---|---|---|---|---|---|---|---|
| Accuracy | 98.3% | 96.0% | 95.7% | 92.8% | 80.2% | 57.5% | **2.5%** |

**QAT at 3-8-3** (300 steps, FP teacher):

| Training data and loss | Accuracy |
|---|---|
| PTQ (no training) | 57.5% |
| Real data, logits distillation | 97.3% |
| **Generated (sampled), logits distillation** | **96.5%** |
| Generated (sampled), hard labels | 97.3% |
| Generated (hybrid), logits | 68.2% |
| Generated (top-1), logits | 54.3% |

**2-bit weights (2-8-8):** PTQ 2.5% → QAT on real data 97.3%, QAT on **generated** data **96.7%**.

**Takeaways:**
- **Data-free QAT works:** the model's own sampled generations are as good as real data, and QAT rescues settings where PTQ collapses.
- **Diversity matters:** top-1 data is useless.
- **Honest note:** soft and hard labels did equally well here; the paper found logits distillation better.

**Simplification:** our "KV cache" quantization is applied to the key/value projections' outputs before RoPE.

**`experiments.py`:**

- **E2:** data sources including hybrid with k = 1–5 and copy-only "WikiText-like" data;

## 6. Check yourself

1. What is the difference between PTQ and QAT?
<details><summary>Answer</summary>PTQ quantizes an already-trained model using only a little calibration data and no (or minimal) training. QAT keeps training the model with quantization simulated in the forward pass, so the weights adapt to rounding. It is more accurate at low bits but needs data and compute.</details>

2. Why is data a problem for QAT of LLMs?
<details><summary>Answer</summary>The pre-training corpus is enormous and often private. Training on a small public dataset instead makes the model over-fit to that domain and lose general (zero-shot) ability.</details>

3. How does LLM-QAT get its training data?
<details><summary>Answer</summary>The full-precision model generates text from the start token: top-1 for the first 3–5 tokens, then sampling (hybrid). 100k such sequences serve as QAT data.</details>

4. Why distil logits rather than train on the generated tokens?
<details><summary>Answer</summary>Sampled tokens are noisy labels (sampling picks less likely tokens too). The teacher's full next-token distribution carries much more information about what the student should predict.</details>

5. What does the straight-through estimator do?
<details><summary>Answer</summary>In the forward pass values are rounded to the quantization grid. In the backward pass the rounding is treated as the identity, so gradients reach the underlying full-precision weights, which keep learning.</details>

6. Why no clipping in the quantizer?
<details><summary>Answer</summary>LLM weights and activations have important outliers. Clipping them destroyed accuracy (perplexity over 10,000), so symmetric MinMax, which keeps the outliers exactly, works better.</details>

7. Why quantize the KV cache per token?
<details><summary>Answer</summary>Keys and values are created one token at a time and appended to the cache, so a per-token scale can be computed when each token is written, without revisiting old entries.</details>

8. What does "4-8-4" mean, and why is it hard for PTQ?
<details><summary>Answer</summary>4-bit weights, 8-bit activations, 4-bit KV cache. Four-bit keys and values distort attention badly, and PTQ can't adapt the model to it. In the paper all PTQ methods failed there, while LLM-QAT was 1.5 points from full precision.</details>

9. Hybrid sampling failed in our toy. Why?
<details><summary>Answer</summary>In our tiny language the first generated token is the task token. Choosing it by argmax always picks the same task (sort), so the generated data covers only one task and the student never practises copy or reverse.</details>

10. In our toy, 2-bit PTQ gave 2.5% accuracy but data-free QAT gave 96.7%. What changed?
<details><summary>Answer</summary>QAT trained the weights (through the STE) to work under 2-bit rounding, distilling the teacher's predictions on its own generated sequences. PTQ just rounded the original weights, whose errors added up and destroyed the model.</details>
